# VS Code

Open the repository **folder** (`code .`). That is all: the tracked files make it work.

| File | Tracked | Does |
|---|---|---|
| `.clangd` | yes | points clangd at `build/compile_commands.json` (any editor, not only VS Code) |
| `.vscode/settings.json` | yes | machine-independent defaults: presets on, clangd as the only IntelliSense |
| `.vscode/tasks.json`, `launch.json`, `extensions.json` | yes | tasks, debug configurations, recommended extensions |
| `build/compile_commands.json` | no | a link to the **last configured preset's** database, maintained by CMake (`cmake/editor.cmake`) |
| `eZeGo.code-workspace` | no | optional, generated by `./ez init` / `./ez vscode`: machine paths such as the Tracy binary |

Switching the preset in the CMake Tools status bar reconfigures that preset, which re-points
`build/compile_commands.json`, so code intelligence always matches the mode you are building
(for example, `EZ_PROFILER` code is live in `profile` and greyed out in `debug`).

Install the recommended extensions when prompted: CMake Tools, clangd, CodeLLDB, and the Microsoft
C/C++ extension (only for its Windows debugger; its IntelliSense is disabled in favour of clangd).
Personal preferences go in your user settings, not in the tracked `.vscode/settings.json`.

### If you see red squiggles everywhere

clangd has no compile database yet. Run `./ez init` (or configure any preset), then
**clangd: Restart language server** from the command palette. `clangd --check=src/apps/ezego/main.cpp`
in a terminal shows exactly what clangd sees.

## Everything without a terminal

| Want | Click |
|---|---|
| Switch mode | CMake Tools status bar → configure preset: `debug` / `profile` / `release` / `asan` / `tsan` |
| Build | status bar **Build**, or F7 |
| Run / debug | pick the target (`ezego`) → F5 → "Debug app (LLDB)" (Windows: "Debug app (Windows)") |
| Tests | Testing view (CTest via CMake Tools) |
| Profile | select the `profile` preset → F5 → "Run app + Tracy", or the task **ez: profile** |
| doctor / init / deps / tools / check | Terminal → Run Task → `ez: …` |

Every task runs the same canonical command as the terminal (`cmake -P scripts/<task>.cmake`), so
the two can never disagree.
